# 续跑只读主文件，阶段记录凭空蒸发

**问题**（第三轮评审 LS-01，respx 复现）：`harvest --resume` 的 `carried` 只读
`records.jsonl`，而已提交的阶段补全（顶会/整卷/滚雪球）在 `records_*.jsonl` 里——
续跑后两条阶段记录从语料消失，新 manifest 却照抄阶段 `complete` 结局。后果链：
`find_gaps`（declared⊆executed）不报警 → PRISMA 识别数按记录文件统计而静默少算 →
滚雪球补回的文献在召回证据里凭空蒸发 → 退出码 0。同型：reclassify 漏写
canonical_records（自产 run 过不了 verify）；triage 候选不查 is_retracted（机器
定谳撤稿）；`--sources` 拼错静默跳过。

**approach**：写「含阶段 fixture 的续跑用例」先红后绿；`carried` 改用既有的
`read_all_records`（found_by∩retry_hashes 过滤天然限定重跑范围）。四条缺陷全部
先构造复现、再修、再补回归用例。

**落进哪里**：harvest.py 续跑段注释 + 四个回归用例（test_harvest_resume /
test_cli reclassify / triage / TestSourcesValidation）。共性教训：**凡「多个写入
点共写一份真相」的地方（records*.jsonl / manifest counts / included.jsonl），
每个读取点都必须问一句——我读的是全部写入点吗？**
