# 互斥的模板会一路绿灯到运行时

**问题**：`references/PARADIGM.md` 的 style_profile 模板写 `"schema_version": "1.0"`，
`references/TEMPLATES.md` 写 `"2.0"`，而 `profile.py` 强制 `!= "2.0"` 即抛
`AuditInputError`。评审复现：照 PARADIGM.md（正是指导生成该文件的指定参考）填出
的 profile 被审计器拒绝，exit 2。两份 references 给出互斥契约，没有任何机制在
合入前发现——错误要等到**用户跑审计的那一刻**才爆。

## approach 与教训

1. **失败是显性的，所以只是 P1 不是 P0。** exit code、报错文案都干净——这救了
   可诊断性，但没救可用性：指定的参考文档产出的文件被自己的工具拒绝，
   用户视角就是"照说明做做错了"。
2. **文档里的 JSON 模板是代码，不是散文。** 散文漂移顶多误导，模板漂移会
   直接产出被拒绝的输入。test_document_contract 原本只锁短语禁令，
   恰好是这类"模板即契约"的内容漏在外面。
3. **修法是让测试读所有 references 里的 json 围栏**：扫描 `~~~json` 块中的
   `schema_version`，≠ 2.0 即 fail（test_document_contract 新增用例）。从此
   任何人在任何文档里改这个字段，测试先于用户报错。
4. **推广**：凡是"文档内嵌 JSON/ YAML 模板 + 代码校验 schema"的组合，都该有
   一条契约测试直接 parse 文档里的模板去撞校验器。同类问题后来在同一轮评审中
   又抓到两处（vendor_names 激活条件、citation_density no-op）——都是
   "文档说有、代码说无"，读文档的人无从分辨。
